# Technical Architecture Overview

## Solution Structure

```
InstantBot.sln
├── src/
│   ├── InstantBot.Domain/           # Core business logic, no dependencies
│   ├── InstantBot.Application/      # Use cases, interfaces (→ Domain)
│   ├── InstantBot.Infrastructure/   # External services implementation (→ Application)
│   ├── InstantBot.TelegramBot/      # Bot entry point (→ Application + Infrastructure)
│   └── InstantBot.AdminPanel/       # Web admin UI (→ Application + Infrastructure)
└── tests/
    ├── InstantBot.Domain.Tests/
    └── InstantBot.Application.Tests/
```

## Domain Layer

**Entities** (all with private constructor + static `Create()` factory):

| Entity | Key Fields | Business Rules |
|---|---|---|
| `User` | TelegramUserId, SubscriptionTier, DailyQuestionsUsed, CurrentStreak, ReferralCode | `CanAskQuestion()`: Free ≤ 3/day; `UpdateStreak()`: consecutive days |
| `PersonalityProfile` | LifePathNumber, DestinyNumber, SoulNumber, ArchetypeType, Strengths/Weaknesses | Generated once on registration |
| `Conversation` | UserId, Summary, LastMessageAt | `Touch()` on new message; `UpdateSummary()` when >20 messages |
| `Message` | ConversationId, Role, Content, TokensUsed | Immutable after creation |
| `DailyCard` | UserId, Date, TarotCard, DayAdvice, DayFocus | Unique per user per day; `MarkViewed()` |
| `Subscription` | UserId, Plan, Tier, StarsPaid, ExpiresAt | ExpiresAt = now + plan months |
| `RelationshipAnalysis` | UserId, PartnerName, PartnerBirthDate, Strengths, ConflictZones | Generated by OpenAI |
| `Referral` | ReferrerId, ReferredId, BonusGranted | One-time bonus per referral |
| `Achievement` | UserId, Type | Unique per user per type |

**Value Objects:**
- `TarotCard(Name, Arcana, Meaning)` — sealed record, immutable

**Enums:**
- `SubscriptionTier`: Free=0, Premium=1, Vip=2
- `SubscriptionPlan`: OneMonth=1, ThreeMonths=3, TwelveMonths=12
- `UserBotState`: None, AwaitingName, AwaitingBirthDate, MainMenu, AwaitingMentorQuestion, AwaitingPartnerName, AwaitingPartnerBirthDate
- `ArchetypeType`: Leader, Diplomat, Creative, Organizer, Adventurer, Nurturer, Seeker, Authority, Sage, Visionary, Builder
- `AchievementType`: FirstQuestion, Streak7, Streak30, FirstReferral, PremiumSubscriber, VipSubscriber, FirstRelationshipAnalysis
- `MessageRole`: User, Assistant
- `AchievementType`: 7 types

## Application Layer

### CQRS Commands

| Command | Handler | Side Effects |
|---|---|---|
| `RegisterUserCommand` | Creates User + PersonalityProfile; handles referral bonus | DB write; referrer gets +7d Premium |
| `AskMentorCommand` | Calls OpenAI; saves messages; updates streak/achievements | DB write; returns response or limit flag |
| `PurchaseSubscriptionCommand` | Updates User.SubscriptionTier and ExpiresAt | DB write |
| `AnalyzeRelationshipCommand` | Calls OpenAI relationship analysis | Returns analysis string |
| `ProcessReferralCommand` | Grants referrer Premium bonus + achievement | DB write + notification |

### CQRS Queries

| Query | Returns |
|---|---|
| `GetDailyCardQuery` | `DailyCard?` for today's date for given user |

### Services (pure, no DI)

| Service | Purpose |
|---|---|
| `NumerologyCalculator` | `CalculateLifePathNumber(DateOnly)`, `CalculateDestinyNumber(string)`, `CalculateSoulNumber(string)` |
| `ArchetypeAnalyzer` | Maps LifePathNumber → `ArchetypeInfo` (name, strengths, weaknesses, recommendations) |
| `PersonalityProfileBuilder` | Composes numerology + archetype → `PersonalityProfile` entity |
| `StreakService` | `CheckAndAwardAchievementsAsync(User)` — awards Streak7/Streak30 |

## Infrastructure Layer

### Persistence

- **AppDbContext** — EF Core 9, `ApplyConfigurationsFromAssembly`, Npgsql
- **Configurations** — fluent API per entity: indexes, constraints, owned types (TarotCard), array columns (`text[]`)
- **Repositories** — implement Application interfaces, use EF Core queries

### OpenAI Integration

| Service | Model | Purpose |
|---|---|---|
| `OpenAiService` | gpt-4o-mini | Mentor responses with user context injection |
| `WhisperService` | whisper-1 | Voice message transcription (VIP) |
| `TtsService` | tts-1 (voice: alloy) | Text-to-speech response (VIP) |

**Context injection in system prompt:** user name, age, LifePathNumber, archetype name, strengths.  
**Token limits:** Free=300, Premium=600, VIP=1000.  
**Summarization:** When conversation >20 messages → background job summarizes to `Conversation.Summary`.

### Redis Cache

All keys use `ICacheService` interface. Implementation: `RedisCacheService`.

| Key Pattern | TTL | Use |
|---|---|---|
| `state:{uid}` | 30m | FSM state |
| `session:{uid}:{key}` | 30m | Temp FSM values (name, partner name) |
| `rate:{uid}` | Until midnight UTC | Daily question counter |
| `offer:{uid}:{type}` | 24h–7d | Upsell offer deduplication |
| `card:{uid}:{date}` | 24h | Daily card JSON cache |
| `admin:dashboard` | 1h | Dashboard metrics cache |

### Background Jobs

All jobs run inside `NotificationScheduler` (BackgroundService, 1-minute tick):

| Job | Schedule | Action |
|---|---|---|
| `DailyCardJob` | 08:00 UTC | Generate + cache + push cards to all active users (batch 50) |
| `InactivityJob` | 10:00 UTC | Send re-engagement offers to 3-day and 7-day inactive users |
| `SubscriptionExpiryJob` | Every 6h | Remind users 3 days before expiry; offer discount on expiry day |
| `ConversationSummaryJob` | Every hour | Summarize conversations with >20 messages |

### Payment Flow

`TelegramStarsService` (static helper) builds invoices.  
Currency: `"XTR"` (Telegram Stars).  
Payload format: `"{Tier}:{Plan}:{userId}"` — parsed in `PaymentHandler.HandleSuccessfulPaymentAsync()`.

## TelegramBot Layer

### Long Polling

`BotPollingService` (BackgroundService) → `bot.StartReceiving()` → per-update DI scope → `UpdateRouter`.

### FSM (Finite State Machine)

State stored in Redis with 30-minute TTL. Managed by `UserStateManager`.

```
/start (new user)
  → AwaitingName
  → AwaitingBirthDate
  → MainMenu (profile shown)

MainMenu callbacks:
  ask_mentor → AwaitingMentorQuestion → MainMenu (answer shown)
  relationship (Premium+) → AwaitingPartnerName → AwaitingPartnerBirthDate → MainMenu
  daily_card → show card (no state change)
  subscription → show plan keyboard
  my_profile → show profile card
  invite_friend → show referral link
```

### Update Routing

```
Update →  UpdateRouter
           ├── Voice message → VoiceHandler (VIP only: Whisper → GPT → TTS)
           ├── Successful payment → PaymentHandler
           ├── Text message → MessageHandler (dispatches by FSM state)
           ├── Callback query → CallbackHandler (menu actions, subscription)
           └── PreCheckoutQuery → PaymentHandler
```

## AdminPanel Layer

ASP.NET Core MVC. Auth: JWT stored in HTTP-only cookie.

Routes:
- `GET  /Auth/Login` — login form
- `POST /Auth/Login` — validates against config credentials, issues JWT cookie
- `GET  /Auth/Logout` — clears cookie
- `GET  /Dashboard` — metrics (cached 1h in Redis)
- `GET  /Users?page=N&tier=X` — paginated user list
- `GET  /health` — liveness check (PostgreSQL + Redis ping)

## Data Flow: AI Mentor Request

```
1. User sends text message
2. MessageHandler → state == AwaitingMentorQuestion
3. AskMentorCommand dispatched via MediatR
4. Handler loads User (with PersonalityProfile) from DB
5. Checks CanAskQuestion() → if false, return LimitReached
6. Loads recent N messages from Conversation (N = tier-based)
7. Builds system prompt: role + user context (name, age, archetype, strengths)
8. Sends to GPT-4o-mini with token limit by tier
9. Saves user message + assistant response to DB
10. Updates DailyQuestionsUsed, Streak, Achievements
11. Returns (response, questionsLeft)
12. MessageHandler sends response text to Telegram
13. If limit reached → upsell message + offer flag in Redis
```

## Security Considerations

- Bot token in env var only, never in code or config files
- OpenAI key in env var only
- Admin JWT secret minimum 32 chars, cookie is HttpOnly
- Telegram payment signature verified by Telegram infrastructure
- No user PII logged (only telegramUserId, response time, token count)
- All responses use disclaimer language ("возможно", "один из вариантов") — no predictions of future
- AI never claims to guarantee results — required by spec and enforced in system prompt
